# Website Craft

## 1. Open with the reference invitation
At the start of every new website task, tell the person:
"For a more tailored result, share a reference from Behance, Cosmos or Dribbble. It helps clarify the layout, typography and mood. No reference? I can still work from your brief."
If a reference is already supplied, acknowledge it and ask what to retain. Do not keep asking for another. A reference is optional and is not permission to copy imagery, logos or protected work.

## 2. Make the brief usable
Identify the business, audience, main action, real offer and material available. Ask essential missing questions together, with reasonable defaults. Preserve the requested stack and existing site unless a change is approved. Summarize the chosen direction before coding. Never invent customers, testimonials, metrics, certifications, prices or production dashboards. Label demonstration content.

## 3. Choose a direction, not an industry stereotype
Read references/industry-sets.json. Select by audience, business job, available content and tone, then offer two coherent directions when the brief leaves room. Farming does not mandate green; software does not mandate dark neon. Avoid reducing every brief to a hero, three feature cards and testimonials. Explicit user references and brand rules override catalog suggestions.

Write a short design contract: primary task; information order; composition; type roles; palette; image roles; interaction; mobile recomposition; exclusions. Each decision needs a reason rooted in this business. Use a distinctive focal point, legible type, purposeful spacing and restraint or density as appropriate to the direction. A playful, colourful or maximal composition can be as intentional as a quiet one.

## 4. Build the asset set before decorating
Use assets/catalog.json. Each item has a role, source, rights, delivery mode, crop/colour guidance, accessible-description guidance, fallback and exclusions. Select a family with coherent image lighting, line weight, perspective and tone. Change treatment to suit the site without falsifying product appearance. Do not force photos where a real product surface or original diagram is more useful. Never imply a stock farm is the actual business, a shield proves security, or a leaf proves organic certification.

Bundled original SVG motifs are editable starting material, not mandatory heroes. Live photo and inspiration sources are links, not cleared downloadable stock packs. Locate the original asset, inspect it and check its exact current licence before use. Keep notices with redistributed files. No paid generators, accounts or plugin installation without the person's approval. See references/rights.md.

## 5. Implement the selected plan
Use semantic HTML, correct heading order, real links and buttons, useful labels and visible focus. Include readable colour contrast, responsive images and dimensions, keyboard use and reduced-motion fallbacks. Mobile should recompose, not merely shrink desktop. If no browser or file tools are available, return code and a test checklist, and state that execution remains undone. Never simulate a successful form submission; wire the endpoint only when provided and approved, otherwise mark it as a demo.

Optional scroll-led route: references/resources.md links Nate Herk's scroll-craft. Choose it only when the story benefits from motion. Review selected source code, retain MIT notices for reused code and keep static/reduced-motion content usable. No automatic install or generation spend.

## 6. Check meaningful variety
For a fresh brief, record the design contract in the project's own variation log, not a global collection of client data. Compare against earlier work available in that project. If the result repeats the same structure with colour changes, revise the information order, composition or image approach for a real content reason. Do not randomize brand rules to pass a number. Use references/variation-review.md for a paired-output exercise.

## 7. Inspect, fix and report truthfully
Render phone, tablet and desktop layouts. Inspect actual screenshots for crop, contrast, hierarchy, overflow and empty space. Check keyboard focus, menus/forms, links, image failures and reduced motion. Run automated checks when available but do not call them proof of design quality or accessibility certification. Fix material defects, inspect again, then list the tested widths, checks, failures and limits. Never claim universal agent compatibility or guaranteed superiority. See references/validation.md.
